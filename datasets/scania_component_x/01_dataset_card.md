## 2. 실측 데이터인가 — **실측(real-world), 단 공개를 위해 섭동(perturbation)·익명화 처리됨**

이 데이터셋은 이전 두 예시(Azure 합성 데이터, 자체 제작 가상 군장비 데이터)와 달리 **실제 SCANIA 트럭 함대에서 수집된 실측 데이터**다. 논문(§2.2 Preserving Data Privacy)이 다음을 명시한다:

- "판독 빈도와 수리 빈도가 수정되었을 수 있으며 실제 트럭 사용을 그대로 대표하지 않는다"
- "운영 데이터와 수리율에 스케일링 등의 섭동이 가해졌다"
- "변수명은 기밀·영업비밀 보호를 위해 모두 익명화되었다"
- 차량 식별자도 익명 ID로만 제공되며, 워크숍 방문 이력이 있는 차량의 무작위 부분집합만 포함

**결론**: 실측 기반이지만 **가공되지 않은 원본 그대로는 아니다.** "완전 합성"과 "완전 실측" 사이의 중간 지점 — 산업계가 실제로 공개하는 데이터의 전형적 형태(고장률 등 민감정보는 섭동, 구조와 상대적 경향은 보존)로 이해해야 한다. 논문은 "섭동이 예측모델의 정확도를 훼손하지 않음을 민감도 분석으로 검증했다"고 밝힌다.

## 3. 규모 (train split 기준, 본 예시가 사용한 부분)

| 파일 | 내용 | 규모 |
|---|---|---|

본 예시는 **8개 단일값 누적카운터**(`171_0,666_0,427_0,837_0,309_0,835_0,370_0,100_0`)만 사용했다. 나머지 6개 히스토그램 변수(167/272/291/158/459/397, 총 96개 빈)는 계산 단순화를 위해 이번 실행에서 제외했다 — [02_domain_mapping.md](02_domain_mapping.md) §2에 명시.

## 4. Component X는 무엇인가

논문에 따르면 **트럭 엔진 계통의 한 익명화된 구성품**이다. 정확한 명칭·기능은 영업비밀로 비공개다. 즉 이 데이터셋은 **단 하나의 구성품**만 다룬다 — Azure/가상군장비 예시처럼 "4개의 서로 다른 구성품(고장모드)"을 비교하는 구조가 아니다.

## 5. "3~5개 고장모드" 요구를 이 데이터로 어떻게 충족했는가

원 프롬프트는 3~5개 고장모드 비교를 요구했지만, 이 실측 데이터는 구성품이 하나뿐이다. 억지로 여러 고장모드를 지어내는 대신, **이 데이터가 실제로 제공하는 축**을 썼다:

- `Spec_3`(차량 사양, 익명 범주 4종: Cat0~Cat3)로 함대를 4개 그룹("형상A~D")으로 나누고, **동일 고장모드(Component X 고장)가 차량 사양에 따라 발생도·심각도·검출도가 어떻게 달라지는가**를 FMECA 워크시트의 4개 행으로 구성했다.
- 이는 이전 두 예시에서 "보너스 발견"으로 다뤘던 형상별 위험도 차이 서사를 **이 데이터셋에서는 주축 구조**로 삼은 것이며, 데이터가 실제로 지지하는 real finding이다 — [outputs/occurrence_stats.csv](outputs/occurrence_stats.csv) 참조.
- 추가로 `Spec_2`(21개 범주)에서 관측되는 극단적 위험도 격차를 보너스 사례로 다룬다 — [outputs/spec2_case.json](outputs/spec2_case.json).

## 6. 데이터셋 선정 사유

| 기준 | 충족 여부 |
|---|---|
| 정비이력(수리기록) + 센서 로그 동시 보유 | ✅ train_tte(수리기록) + train_operational_readouts(계측) — 실측 데이터로는 드문 조합 |
| 고장 라벨 | ✅ in_study_repair (이진), 명확 |
| 구성품/차량 단위 식별자 | ✅ vehicle_id, Spec_0~7로 형상 계층 구성 가능 |
| 라이선스 명확성 | ✅ CC BY 4.0, 학술·사내 검토 목적 사용 가능 |
| 실측 여부 | ✅ 실측(섭동 처리됨) — 이전 두 예시의 한계(합성 데이터)를 보완 |

NASA ADAPT(항공우주 전력계통)도 검토했으나, 실험실 결함주입 데이터라 "운용시간 누적에 따른 자연 발생 고장률(O)"을 계산할 기반이 없어 이번 파이프라인 구조와 맞지 않았다 — 상세 사유는 대화 기록 참고. NASA C-MAPSS/N-CMAPSS(항공기 엔진)는 시뮬레이션이라 실측 요구조건에 맞지 않았고, NASA SMAP/MSL(우주선)은 실측이지만 "정비/부품교체" 개념이 없어 RCM·LORA·보급소요 체인을 적용할 근거가 없었다.
